## 1) عندما يرسل عبدو تقرير GPT ويطلب التحقق
أ) أمر واحد: git rev-parse HEAD؛ git status --short؛ git log --oneline -6؛ git show --stat --format='%H %s' لكل commit مذكور؛ git diff --stat <baseline> HEAD -- [الملفات المحظورة].
ب) اقرأ الكود الذي يذكره التقرير (grep/sed) وقارنه بالادعاء.
ج) شغّل typecheck والاختبارات وقارن العدد.
د) افحص ملف التسليم نفسه بحثًا عن أسطر قديمة متناقضة: grep -n "لم يبدأ\|⏳" . ملاحظة: مطابقات هذا الأمر داخل الأقسام المعلَّمة بتنبيه تاريخي لا تُعد تناقضًا.
هـ) شكل الرد: جدول (بند التقرير | النتيجة ✅/❌) ← «ملاحظات وليست أخطاء» ← «ما لم أتحقق منه» ← حكم صريح.
لا تعتبر التقرير حقيقة لأنه مكتوب. كل ادعاء يُفحص.

## 2) عندما يطلب عبدو «أعطني ما ينفذه GPT»
أولًا افحص: خريطة الاستيرادات (grep)، الاختبارات وvi.mock، tsconfig وvite وsw.js، وعرف التسمية الموجود.
ثم اكتب رسالة GPT بهذا الهيكل بالترتيب:
1. [قرار عبدو]: البند الواحد ومراحله.
2. [رد Claude] للتسجيل، بصيغة «بحسب النص الذي وصل GPT».
3. القواعد والممنوعات، مع أي استثناء مصرّح به بالاسم (مثال: سطر استيراد واحد في App.tsx).
4. Baseline: الأوامر مع القيم المتوقعة (HEAD، status، عدد الاختبارات).
5. المراحل: كود ثم توثيق، لكل واحدة commit مستقل.
6. لكل مرحلة: التعديلات الدقيقة (من ← إلى)، والتحقق بأرقام متوقعة، ورسالة commit.
7. شرط التوقف (قاعدة دائمة من 2026-09-23): المشاكل الصغيرة — أي شيء يمكن حله ضمن نطاق الملفات المسموحة نفسه دون تغيير سلوك مطلوب (مثال: فشل اختبار سببه طريقة المطابقة لا السلوك الفعلي) — يحاول GPT حلها بنفسه، ويكتب في تقريره **بمصداقية كاملة**: ما واجهه، وكيف حلّه، ولماذا. المشاكل الكبيرة — أي شيء يتطلب الخروج عن الملفات المسموحة، أو تغيير سلوك غير مذكور في القرار، أو الحل غير واضح — توقف فورًا وأبلغ، ولا تحاول الحل من تلقاء نفسك.
8. تقرير الإرجاع الإلزامي.
9. «لا تبدأ بندًا آخر دون قرار جديد».
قاعدة الأرقام المتوقعة: احسبها بأمر (عدّ ملفات grep أو git diff --stat) ولا تحسبها ذهنيًا. وفضّل كتابة قائمة الملفات على كتابة عددها.

## 7) التنسيق بين Claude وGPT — قاعدة صارمة
- عندما يحتاج Claude شيئًا من GPT (فحصًا، تنفيذًا، أو توضيحًا)، أو عندما يقترح Claude على عبدو الخطوة التالية أو بندًا تنفيذيًا: يجب أن يكتب **البرومبت الجاهز الكامل القابل للنسخ والإرسال إلى GPT داخل نفس الرسالة فورًا**، لا في رسالة لاحقة منفصلة، ولا بعد سؤال عبدو «أرسله؟». يجب أن يحتوي البرومبت نفسه على القرار/النطاق، القواعد والممنوعات، الـBaseline المتوقع، خطوات التنفيذ أو التحقق، شروط التوقف، وما يجب أن يعيده GPT في التقرير، بحسب طبيعة الطلب.
- ممنوع صراحة أن يقول Claude "جاهز، قل لي وأكتبه" أو "أخبرني إن أردت البرومبت" أو أي صياغة تُرجئ كتابة البرومبت لدورة رد إضافية. إذا تقرر البند التالي (باختيار عبدو أو بترتيب متفق عليه مسبقًا)، البرومبت يُكتب فورًا في نفس الرد.
- الاستثناء الوحيد: عندما لا يزال البند نفسه غير محدد (مثلًا عبدو لم يختر بعد أي بند من قائمة)، عندها يُطرح السؤال فقط دون برومبت، لأن البرومبت غير ممكن كتابته بدقة قبل تحديد البند.
- عبدو ينقل البرومبت كما هو دون الحاجة لطلب إضافي من Claude.
- إذا كان الاقتراح يحتاج إلى اختيار عبدو أولًا، يمكن سؤال عبدو عن الاختيار فقط. **بمجرد أن يختار عبدو البند أو يحدد الإجراء، يجب أن يظهر البرومبت الكامل في نفس رسالة Claude التي تقدم الخطوة التالية، وليس في رسالة لاحقة.**

- نمط «فئة ← ملف» في `SettingsView` يختلف عن نمط «اهتمام وظيفي ← hook» في `App.tsx`؛ الثاني لا يتطلب فصل كل شيء، وبعض المنطق مثل تسلسل الإقلاع يبقى في مكانه الطبيعي بقرار واعٍ.
- **حادثة package.json (أثناء فحص Baseline قبل بند #3):** ظهر `M package.json` غير متوقع في `git status`، وكان الفرق الوحيد إضافة تلقائية لحقل `"packageManager": "pnpm@..."` بسبب تشغيل أمر عبر `pnpm` بدل `npm` في مكان ما من الفحص. هذا أثر جانبي معروف موثّق أصلًا في قاعدة العمل 13 (القسم 24 من ملف التسليم). التعامل الصحيح: `git checkout -- package.json` لإلغاء التغيير غير الملتزم، ثم إعادة فحص Baseline كاملًا من الصفر (HEAD + status + typecheck + tests) قبل المتابعة — ولا يُعتبر هذا تعديل dependencies حقيقي أو عملًا يحتاج قرار عبدو بحد ذاته لأنه إلغاء أثر عرضي غير مقصود، لا تغيير مقصود. الدرس: **لا تستخدم pnpm إطلاقًا في أي أمر فحص أو تحقق**، فقط npم.
- **اكتشاف مصدر صوت بديل (2026-09-23):** أثناء التخطيط لميزة التلاوة المتصلة، ظهر أن `api.islamic.app` يوفر endpoint واحد (`/v1/audio/reciters`) يرجع قدرات كل قارئ (`audioLevels: ["ayah"]`/`["surah"]`) دفعة واحدة، بديل أنظف من الفحص اليدوي قارئ قارئ على `cdn.islamic.network`. لم يُتحقق منه Live بعد داخل المشروع؛ أول برومبت GPT لهذا البند فحص فقط.
